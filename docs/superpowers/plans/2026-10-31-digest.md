# Digest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tóm tắt hội thoại nhóm Telegram (theo khoảng thời gian, đoạn, hoặc tin tự chọn) thành kết quả có cấu trúc: chốt / thay đổi / ảnh hưởng team / cần confirm / việc cần làm / chủ đề.

**Architecture:** `digest.py` (service mới) đọc tin live qua Telethon, kiểm consent theo chat (bảng `digest_consents`), gọi provider qua `AiService._call`, parse JSON. UI là `digest-page.tsx` thay chỗ `MessageList` khi bấm "Tóm tắt". Độc lập với luồng tag/draft.

**Tech Stack:** FastAPI + Pydantic v2, Telethon, SQLite; Next.js static export + TanStack Query; pytest.

**Spec:** [2026-10-31-digest-design.md](../specs/2026-10-31-digest-design.md)

## Global Constraints

- Tối đa 400 tin / 80.000 ký tự mỗi lần tóm tắt; consent 1–90 ngày, mặc định 30.
- Team mặc định: `Web, Mobile, Backend, QA, Design`; ≤ 10 team, mỗi tên ≤ 30 ký tự.
- Không ghi nội dung tin hay kết quả Digest xuống đĩa; không log nội dung.
- Mã lỗi: `digest_consent_required` (403), `digest_too_large` (422), `digest_empty` (422), `not_connected` (503), `ai_permission_changed` (409), `ai_not_configured` (503).
- UI tiếng Việt; theo token/màu của các component hiện có.
- Lệch so với spec (đơn giản hơn): `history` trả `{items, truncated}` thay vì header `X-Truncated`.

## Review Focus

1. Consent thu hồi trong lúc AI chạy → 409, không trả kết quả.
2. AI trả JSON bọc ```json … ``` hoặc JSON hỏng → vẫn hiển thị (parse hoặc `raw`).
3. AI bịa `message_ids` không có trong đầu vào → bị lọc.
4. Khoảng có > 400 tin → 422 `digest_too_large`, không gọi provider.
5. `message_ids` thuộc chat khác / không tồn tại → bị bỏ (server chỉ dùng tin đọc từ Telegram của đúng `chat_id`).
